# Skill 升级判断规则

不要把每个需求都做成 Skill。知识应进入最小、最贴切的载体。

| 载体 | 适用情况 | 判断标准 | 记录位置 |
| --- | --- | --- | --- |
| 一次性要求 | 只对当前交付有用 | 不会稳定复用 | 任务卡 / PR 描述 |
| Project Rule | 同一项目反复必须遵守 | 项目专属、违背会造成返工或风险 | `RULES.md` |
| Decision | 需要保留“为什么如此选择” | 存在可替代方案或未来可能质疑 | `DECISIONS.md` |
| Template | 输出结构反复相同 | 替换内容即可复用 | `templates/` |
| Skill | 跨项目、跨任务的稳定方法 | 已至少验证两次，输入/输出/检查步骤明确 | `skills/<skill>/SKILL.md` |

## 进入 Skill 的门槛

以下条件全部满足才可升级：

1. 已在至少两个独立任务中成功验证；
2. 有清晰触发场景、输入、产出与边界；
3. 有可执行步骤和质量检查，不依赖某段聊天记忆；
4. 不包含项目专属路径、临时偏好、密钥或未经确认素材；
5. 维护成本低于每次重新说明的成本。

## 升级流程

1. 在 LEARN 记录候选和两次验证证据。
2. 先写 Template 或项目 Rule；不要直接造大 Skill。
3. 满足门槛后创建/更新 Skill，写清“不适用场景”。
4. 在一次真实任务中验证 Skill，失败则降回 Template 或 Rule。
5. 记录版本、变更原因和可回退版本。

## 禁止事项

- 仅因“可能以后有用”创建 Skill。
- 把完整项目背景、产品偏好或几十条杂项塞进通用 Skill。
- 用 Skill 覆盖项目总控或 Owner 的当前任务决定。
